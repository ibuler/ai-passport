# Pocket Passport 随身名片

首页上方左侧显示上传的名片图、名字和公司，右侧显示时间、日期、城市、天气图标和温度；下方只显示贡献热力图，不显示 GitHub 字样、标题或周数，底部保留一行按键提示。名片区域无单独背景色，首页天气不显示缓存或更新状态文字。长按确定打开小应用列表，七项应用包括小智 / 芙宁娜、音乐、城市收音机、天气、番茄钟、秒表和手机后台。界面独立设计，不沿用硬件测试菜单，也不复制社区玩法 438 的源码。沿用 `feature/pocket-focus` 分支及官方 BSP，基线为 Gitee `main` 的 `a06235e4c94361e3f8a2d498930254101718acae`。

### 手机后台

音乐 / 收音机页先长按确定返回应用列表。长按下键，连接屏幕显示的 Wi-Fi 和密码；即使提示无互联网也保持连接，打开 `http://192.168.4.1`。先验证并保存 2.4 GHz 网络；失败会恢复原网络，切换信道后手机可能需要重新连接。

- **名字与音乐：**填写名字、音量、最多 8 条音乐名称 / MP3 直链，或通过地址 / 本地文件导入 version: 1 的歌单 JSON。地址默认填入提供的 OSS 五月天歌单。全部曲目校验通过后按原顺序替换编辑列表，失败保留原列表和设备配置；检查、编辑后点击“保存名字与音乐”。歌单为 1–8 首、最大 7 KiB，忽略额外元数据，签名音频地址原样保留。设备直接请求 HTTP / 验证证书的 HTTPS JSON 地址（不跟随跳转），不依赖手机跨域权限，需先联网并校时；本地文件可离线导入。保存的是曲目快照，不会自动同步远端歌单。
- **公司、城市与电台：**填写公司，选择常用城市（包含天津）或填写城市名称，设置固定 UTC 偏移；可为各城市保存最多 6 条电台名称 / MP3 直链。点击“保存公司、城市与电台”。已移除经纬度输入框。常用城市在本地匹配位置，原有自定义城市保留已存坐标，新自定义城市在请求天气时通过 Open-Meteo 按名称查询。同名城市使用首个结果，建议填写明确的城市名称。天气和收音机使用同一个配置城市，不读取电脑位置或 GPS。
- **GitHub：**独立的 GitHub ID 输入框和保存按钮，默认为 `ibuler`，留空停止获取并显示默认图。最多 39 位 ASCII 字母、数字及中间的单连字符；单独存入 NVS `github_id` 字符串，保留原有名片配置及图片。
- **名片图：**单独上传 PNG、JPEG、WebP 或 GIF；“保留彩色”“播放动画”独立控制。gifuct-js 2.1.2 在浏览器本地转换，无 CDN 或云转换。输出居中裁剪为 96×96 RGB565，最多 48 帧、间隔 100–2000 ms；输入最大 5 MiB、1024×1024、300 个 GIF 原始帧，长 GIF 会抽帧。

保存后长按确定，关闭热点 / HTTP 并返回应用列表，再长按确定返回首页。名字 / 公司 / 曲目固件上限为 95 个 UTF-8 字节，城市为 63 个；手机界面采用保守字符上限。表情或字体不支持的扩展汉字显示 `?`，通过实际字体检查覆盖与渲染。

### GitHub 贡献图与天气图标

贡献图通过验证证书的 HTTPS 直接读取 GitHub [公开贡献日历](https://github.com/users/ibuler/contributions)，无需 Token 或第三方代理。显示最近 26 周，周日为每列第一行，使用原页面 0–4 级活跃度，未来日期留空；不按仓库提交数推算。分块解析最多 384 KiB HTML，仅保留 512 字节标签及 182 天数据；主体读取有 15 秒上限，打开后台或开始播放时中止；登录页、错误页、截断或缺失日期均校验失败。公开页面格式可能变化；优先保留同一用户的 RAM 旧图，没有有效数据（首次启动、离线、ID 不存在或已留空）时显示内置默认图；首页不显示错误标题。默认图来自开发时读取的 ibuler 公开日历快照（2026-10-22），仅作示例装饰，不代表当前账号的实时贡献，后台有明确说明。切换 ID 时清除前一用户的实时图，重启清除此 RAM 缓存。

联网并校时后获取，与现有 HTTP 互斥锁共用，设置打开或音频活动时暂停。有效数据每小时刷新，没有有效数据时失败每 5 分钟重试；退出手机后台会请求刷新。天气城市留空不影响 GitHub。I4 图片占 5,784 字节，仅一个 LVGL 对象，避免每天一个控件。天气图标按 [Open-Meteo 天气代码](https://open-meteo.com/en/docs)绘制太阳、云、雨、雪、雾和闪电，缺失 / 未知数据使用中性短线，不依赖 emoji 字体。

### 天气与城市收音机

天气使用 [Open-Meteo](https://open-meteo.com/en/docs) 当前温度、天气代码、湿度及风速，按确定刷新，或在音频空闲时每 15 分钟更新。天气应用内对断网、失败、缓存数据有明确状态，不生成天气或切换到其他城市。天气页显示来源。数据为预设、保留或[按城市名称查询的位置](https://open-meteo.com/en/docs/geocoding-api)处的模型估计；城市查询失败时提示天气不可用，不查询上一城市。

收音机采用**网络电台**：[Radio Browser API](https://docs.radio-browser.info/) 使用当前城市名称搜索电台名称，仅筛选 MP3，最多 6 项；不是实体 FM 调谐，也不保证城市覆盖。后台手动条目的城市名称须完全匹配当前城市，有匹配条目时优先使用。无结果或目录不可用时保留提示，可重试或补充已知直播直链。切换城市不能沿用上一城市列表。当前播放器不支持 AAC、HLS、M3U、登录、DRM 或网页分享链接。

音乐支持 HTTP / HTTPS MP3、分块响应及最多 4 次重定向。默认仍为 [Music For Programming](https://musicforprogramming.net/) 第 79 期，只从原站流式读取，不重新分发音频。TLS 使用 IDF 证书包及 SNTP 校时，不关闭验证。暂停过久可能需要从头重播，不支持拖动进度或保存位置。按确定开始音乐后，正常播完自动按歌单顺序切换，最后一首回到第一首。错误停留当前曲目供手动重试，暂停或退出音乐页不会触发切歌；歌名 / 选中项随自动切歌更新，收音机不应用歌单循环。MP3 内存修复后，用户已于 2026-10-22 确认 OSS 音源正常出声；新增音量控制仍需单独真机验收。

## 实现

### 小智与芙宁娜

应用列表新增带芙宁娜形象的小智。按照 [FoloToy 参考项目](https://github.com/FoloToy/folo-ai-passport-xiaozhi/tree/72da544d1b51678f5d88967adc299b3aec956946)的通信协议，在现有 ESP-IDF 5.5.3 BSP 上接入，保留本应用固件、界面、分区和配网流程。参考项目要求 IDF 6.0.1+，没有整套嵌入它的应用。首次按确定从小智官方接口获取激活 / 连接配置；若出现激活码，三分钟内到 [xiaozhi.me](https://xiaozhi.me) 添加设备，否则按确定重试。声音 / 人设由该服务控制台选择，角色图片本身不会改变音色或仿制配音演员。

连续对话上传单声道 16 kHz、60 ms 的 Opus 麦克风数据，使用服务端自动分句。按一次确定开启，识别完成后自动暂停麦克风并以协商的 16 / 24 kHz 播放回答，答完继续聆听；再次按确定关闭会话、停止回答并释放资源。录音 / 回答分别持有编码器 / 解码器，阶段切换时释放缓冲和 BSP 资源，回答期间暂停麦克风；不启用本地唤醒词。使用验证证书的 MQTT / TLS + AES-CTR UDP，或 WebSocket / TLS（帧版本 1–3）。拒绝格式错误 / 截断帧、过期 UDP 序号及其他会话事件。网络和等待回答有上限，网络错误后手动重试，关闭操作等待工作任务完成清理。忽略远端固件 / 系统控制消息，不声明 MCP / 设备控制能力。

九帧透明 128×128 RGB565A8 表情占用 442,368 字节应用 Flash，直接引用，不分配完整图像帧。聆听 / 思考有独立表情，待机眨眼，LLM 情绪事件选择开心、担忧或惊讶的表情点缀；仅在成功输出 PCM 附近使用开合嘴帧，音频停止后闭嘴。这是随发声活动变化的动画，不是逐音素口型同步。UTF-8 字幕沿用现有字体 / 缺字处理。激活码和凭据不输出日志，独立 NVS 命名空间只保存稳定的客户端 UUID，退出后清零临时连接密钥 / 令牌。退出应用会等待网络回调、socket、队列、codec、DMA、缓冲和任务停止完成，再删除界面；连接前协作停止后台数据任务并释放其 8 KiB 栈，退出后重建，保留缓存和刷新请求。语音任务在实测后使用 28 KiB 栈，修复实机在 8 KiB 栈上触发的 SILK 栈保护故障；引导 / 消息 JSON 缓冲改为临时分配，在开始录音前或消息解析后释放。应用及页面名称仅为“小智”，开始对话提示只保留在底部。音乐 / 收音机、原配置和首页图片继续兼容。实际激活、麦克风 / 扬声器音质、音量、打断和反复切换内存稳定性仍需上板验证，主机模拟不能证明云端兼容。

状态、纯模型、界面、持久化、网络及任务都在 `main/pocket`，通过可复用的 BSP 仅播放音频接口，省去未使用的麦克风 DMA。按键只入队，LVGL 访问持 BSP 锁；音频工作任务独占 HTTP / MP3 / I2S，独立后台任务获取天气 / 电台。共用互斥锁串行化 HTTP / TLS 内存分配，设置打开或音频活动时暂停后台请求，控制无 PSRAM 设备的峰值占用。

音频资源由当前歌曲持有：结束、失败、取消和切换都会关闭 HTTP / TLS 与 MP3 解码器、释放输入输出缓冲、休眠 codec 并释放其接口及 I2S 通道 / DMA；共用 I2C 总线保留给电量计。10,240 字节播放任务按需创建，退出应用或切歌时等待清理确认后删除；手动切换和列表自动下一首都先停止完成，再改变选中歌曲并启动播放。停止超时或释放失败时保留当前页面和选中项供重试，不会强制删除仍在工作的任务。暂停会保留当前音频流供继续播放。页面切换已有的图片文件 / 帧释放与旧 LVGL 对象删除继续生效，退出设置会关闭 HTTP 服务和 SoftAP；共用 Wi-Fi、显示、数据获取服务以及少量天气 / 计时状态继续保留。反复切换的真实内存稳定性仍待上板验证。

固定版本 MP3 Layer-3 解码器会在实际解码时分配 27,840 字节工作内存，另有分配器开销。界面池保留 26 KiB（原生回归峰值 18,544 字节），Wi-Fi 静态收包缓冲为 6 个，与默认 6 帧 Block Ack 窗口一致；相比原 32 KiB / 10 缓冲配置，约返还 12 KiB 系统堆，供验证证书的 HTTPS 和 MP3 解码同时使用。证书验证保持开启，音频任务栈大小不变。解码错误记录返回码和内存状态，首次成功写入 PCM 记录音频格式和内存状态。

按键调音量单独保存到 `volume` NVS 字节，启动时覆盖旧 config 中的值，避免播放中复制或重写整份歌单；手机保存配置时同步更新两者。音频工作任务在 PCM 写入之间应用新音量，保持独占音频硬件；暂停时调整会在继续播放时生效。每次长按调整一档，不自动连发。

保留原 `config`、Wi-Fi、图片槽位键，新增独立版本化 `profile` NVS blob，存公司、城市、时区及手动电台。图片使用双文件、长度 / CRC / 帧延时校验，验证完成才切换；RAM 只保留一帧 18,432 字节。设置沿用每次开机生成的 WPA2 密码、受限表单 / 上传及令牌保护的写接口，不回传或记录密码。

按[环境指南](development/engineering/environment-setup.zh_CN.md)安装并激活 ESP-IDF 5.5.3。网页构建和测试使用 Node.js 20 或更新版本。

```bash
cd web
npm ci
npm run build
cd ..
./tools/validate.sh
cmake -S tests/pocket -B build/host-ui
cmake --build build/host-ui -j 8
build/host-ui/pocket-render main/pocket/ui.c main/pocket/player.c main/pocket/model.c main/main.c main/pocket/feeds.c
```

完整门禁包含上游检查、应用模型测试、JavaScript 帧包测试、嵌入网页一致性检查、固件构建、合并镜像验证和按内容哈希保存的调试归档。本地渲染还会用实际 LVGL 字体检查上述设备界面源文件中的所有非 ASCII 字符、已知缺失字形反例，并在与固件一致的 26 KiB 内存池下完整切换 9 页 12 轮、检查最长配置字段及至少 4 KiB 可用余量，并检查断网时钟占位、负温度显示和收音机错误提示保留；输出各页的 PPM 图片到 `build/`。

## 固件与数据

| 分区 | 偏移 | 大小 |
| --- | --- | --- |
| NVS | `0x9000` | `0x6000` |
| PHY | `0xF000` | `0x1000` |
| Factory 应用 | `0x10000` | `0x4F0000` |
| SPIFFS 图片 | `0x500000` | `0x300000` |

验证后的完整镜像包含新的 SPIFFS 卷，从 `0x0` 写入，会替换原固件并重置图片存储，NVS 配置也可能重置。这不是保数据升级；确认刷写前先导出需要保留的数据。不要求全片擦除或读取原固件备份。文件系统挂载失败会报告错误，不会自动格式化已有图片。

`build/firmware/<SHA256>/` 调试归档绑定完整镜像、ELF 和 MAP。额外的 `storage.bin` 已合并进完整镜像，需要分段刷写时另行保存。禁止将 application-only 镜像写入 `0x0`。

分别报告 Build、Host tests、Simulator tests、Device tests、Unverified。真机仍需验证 Wi-Fi 成功 / 失败 / 重启恢复、上传中断、弱网播放 / 暂停 / 切歌 / 停止、扬声器输出、反复资源回收、中文显示和电量 / 功耗。每次烧录前都需要你确认具体固件与设备。
